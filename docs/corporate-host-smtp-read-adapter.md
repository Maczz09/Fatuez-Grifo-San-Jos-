# Adaptador SMTP corporativo preparado

`createCorporateHostSmtpReadAdapter(store, vault)` entrega únicamente los puertos `configurations` y `vault` para `CorporateEmailDependencies`. Recibe instancias ya administradas por el propietario; no crea conexiones, no registra rutas ni habilita envíos. La lectura comprueba empresa, RUC, revisión y versión del sobre; el vault autentica criptográficamente empresa y RUC mediante su AAD. Las excepciones se normalizan sin incluir datos privados. Los puertos son capacidades internas confiables: no deben exponerse por HTTP, logs, respuestas públicas ni entregarse a actores no autorizados; `read` devuelve un sobre cifrado y `open` devuelve bytes sensibles que el consumidor debe borrar.

Integración pendiente: un ensamblador interno debe aportar explícitamente estos dos puertos junto con `permission`, cuya autorización vigente debe validar identidad, RUC, sucursal, documento y destinatario. Debe administrar el ciclo de vida del store, pool TLS y vault, revisar la política de hosts y los permisos, y mantener deshabilitado el envío hasta autorizar expresamente una integración separada. No se ha registrado el adaptador en el runtime, cambiado configuración ni activado almacenamiento o SMTP. Las pruebas usan únicamente un protocolo de pool simulado y clave/datos sintéticos.
