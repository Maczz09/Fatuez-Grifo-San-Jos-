# B2B-09 — enlace aislado de boleta, RC y CDR

El componente `verifyBoletaRcLinked` compone los verificadores existentes con una fuente privada de versión exacta. Comprueba la versión y el hash del snapshot individual, el XML individual firmado, la pertenencia y firma del RC, el ZIP del RC y la aceptación mediante CDR firmado. Coteja el identificador y la línea del RC, el hash del snapshot del lote, los hashes de XML y ZIP del RC y el fence completo de aceptación. No compara el XML individual con el XML del RC. Repite las verificaciones y la lectura del registro, y devuelve un resultado candidato sin autorización de transmisión.

Se mantiene independiente del runtime, contrato y almacenamiento histórico. La fuente privada debe garantizar el significado e inmutabilidad de `member.version`, `ownerVersion` y `loadExact`; este componente no demuestra su procedencia. Las relecturas no son una transacción: cualquier consumidor debe implementar un cerco atómico propietario que cubra documento, versión, lote, catálogo y aceptación, y conservar las guardas de binding y catálogo. No se entrega una capacidad sellada para sustituir los verificadores existentes, ni se demuestra ausencia de una versión posterior, no entrega o aceptación en producción. El fence de aceptación es del RC; `ownerVersion` pertenece al registro individual y no se equipara a aquél.

Las pruebas usan datos sintéticos, firmas XML y CDR de fixtures y política de confianza/CRL simulada del fixture existente. No acreditan PKI productiva, almacenamiento propietario, atomicidad ni homologación fiscal. B2B-09 sigue abierta y no se ha conectado a SUNAT, producción ni una base de datos existente.
